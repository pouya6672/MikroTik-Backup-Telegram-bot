# ربات بکاپ میکروتیک (MikroTik Backup Bot)

[English](README.md) | [Español](README.es.md) | [Русский](README.ru.md) | [中文](README.zh.md) | **فارسی**

ربات تلگرامی برای بکاپ‌گیری خودکار از میکروتیک و ارسال فایل‌ها به پیوی، گروه یا کانال، طبق زمان‌بندی دلخواه شما.

ربات با SSH به روتر وصل می‌شود، بکاپ را می‌سازد، با SFTP دانلود می‌کند، از روی روتر پاک می‌کند و در تلگرام می‌فرستد. هر وظیفه بعداً قابل ویرایش است و خود ربات به 🇬🇧 English، 🇪🇸 Español، 🇷🇺 Русский، 🇨🇳 中文 و 🇮🇷 فارسی کار می‌کند.

## امکانات

- **انواع بکاپ:** بکاپ باینری (`.backup` با رمز یا بدون رمز)، دیتابیس User Manager ‏(`.umb`) یا هر دو
- **زیپ اختیاری:** ZIP معمولی یا ZIP رمزدار با **AES-256**
- **مقصد انعطاف‌پذیر:** پیوی، گروه یا کانال
- **زمان‌بندی انعطاف‌پذیر:** از ۱ ساعت تا ۷ روز، یا بازه‌ی دلخواه مثل `30m`، `2h`، `1d` (حداکثر ۳۰ روز)
- **تلاش مجدد خودکار** برای خطاهای موقتی، با پیام‌های خطای واضح و راه‌حل‌محور
- **منطقه‌ی زمانی برای هر کاربر** (روی نام فایل، ساعت کپشن و «آخرین اجرا»)
- **چندکاربره:** سقف وظیفه برای هر کاربر، سقف بکاپ همزمان، کنترل دسترسی
- **امن به‌صورت پیش‌فرض:** رمزنگاری اطلاعات ورود، پین کردن کلید SSH، بلاک آدرس‌های خصوصی، محدودیت‌های ضد سوءاستفاده
- **آماده‌ی Docker** و اجرا با کاربر غیر root

## پیش‌نیازها

- پایتون **۳.۱۰ یا بالاتر** (یا Docker)
- توکن ربات از [@BotFather](https://t.me/BotFather)
- روتر میکروتیک با SSH فعال که از سرور ربات قابل دسترس باشد
- پکیج‌های پایتون: `python-telegram-bot[job-queue]`، `asyncssh`، `pyzipper`، `cryptography`، `python-dotenv`، `tzdata`

## تنظیم سمت میکروتیک (برای هر روتر)

1. سرویس **SSH** فعال باشد و از سرور ربات قابل دسترس باشد (پورت پیش‌فرض ۲۲ یا هر پورت دلخواه):

</div>

```
/ip service print
```

<div dir="rtl">

2. یک کاربر اختصاصی بسازید و فقط از IP سرور ربات اجازه‌ی ورود بدهید:

</div>

```
/user add name=tgbackup group=full password=STRONG_PASSWORD address=BOT_SERVER_IP/32
```

<div dir="rtl">

   گروه `full` ساده‌ترین حالت است. اگر گروه محدودتری می‌سازید، حداقل این مجوزها لازم است: `ssh, ftp, read, write, policy, test, sensitive`.

3. برای بکاپ User Manager باید پکیج `user-manager` روی روتر نصب باشد.

## نحوه‌ی استفاده

| دستور | توضیح |
|---|---|
| `/new` | ساخت وظیفه‌ی بکاپ |
| `/jobs` | لیست وظیفه‌ها: اجرای فوری، ویرایش، توقف/ادامه، حذف |
| `/timezone` | تنظیم منطقه‌ی زمانی |
| `/language` | تغییر زبان ربات |
| `/cancel` | لغو مرحله‌ی جاری |

### ساخت وظیفه (`/new`)

1. **آدرس:** IP یا دامنه، با پورت SSH اختیاری (`1.2.3.4` یا `1.2.3.4:2222`)
2. **نام کاربری**
3. **پسورد:** پیام شما بلافاصله پاک می‌شود و اتصال همان لحظه تست می‌شود
4. **نوع بکاپ:** میکروتیک / User Manager / هر دو، با یا بدون رمز بکاپ
5. **زیپ (اختیاری):** بدون زیپ / زیپ بدون رمز / زیپ با رمز
6. **پوشه‌ی موقت روی میکروتیک**
7. **مقصد:** پیوی، گروه یا کانال
8. **فاصله‌ی زمانی:** ۱ ساعت … ۷ روز، یا دلخواه (`30m`، `2h`، `1d`)

### زیپ (اختیاری)

اگر فعال باشد، فایل‌های هر اجرا داخل **یک فایل ZIP** گذاشته و همان ارسال می‌شود؛ مثلاً `MyRouter_2026-01-31_12-00.zip` که شامل `.backup` و در صورت انتخاب «هر دو»، `.umb` هم هست. پیش‌فرض «بدون زیپ» است، پس وظایف قدیمی مثل قبل کار می‌کنند.

- **بدون رمز:** ZIP معمولی (Deflate).
- **با رمز:** ZIP با رمزنگاری **AES-256** (استاندارد WinZip). با 7-Zip، WinRAR، Keka، The Unarchiver و مانند آن‌ها باز می‌شود؛ بازکننده‌ی داخلی ویندوز (Explorer) از AES پشتیبانی نمی‌کند. روش قدیمی و ضعیف ZipCrypto عمداً استفاده نشده است.
- رمز ZIP جدا از رمز بکاپ میکروتیک است؛ می‌توانید هر دو را بگذارید (بکاپ رمزدار داخل ZIP رمزدار).
- اگر ساخت ZIP شکست بخورد، فایل‌های بدون زیپ **فرستاده نمی‌شوند** (تا فایلی که رمزدار خواسته بودید، بدون رمز ارسال نشود) و خطا به مالک اعلام می‌شود.
- حجم ZIP نهایی هم باید زیر محدودیت ۵۰ مگابایتی تلگرام باشد.
- بعداً در `/jobs` ← وظیفه ← **✏️ ویرایش** ← **🗜 ZIP** قابل تغییر است.

### پوشه‌ی میکروتیک

مسیری مثل `flash/backups`، `disk1/mt-backup` یا `backups`. با `-` یا دکمه‌ی پیش‌فرض، فایل‌ها در روت ساخته می‌شوند.

- اگر پوشه (یا هر زیرپوشه‌ی مسیر) وجود نداشته باشد، ربات قبل از هر بکاپ آن را با `/file add type=directory` می‌سازد. روی نسخه‌هایی که این دستور را ندارند، پوشه هنگام ذخیره‌ی فایل ساخته می‌شود.
- اگر دیسک (`flash`، `disk1`، `usb1`، …) روی دستگاه وجود نداشته باشد، ربات خطای واضح می‌دهد.
- فایل‌ها بعد از دانلود از روی میکروتیک پاک می‌شوند، پوشه می‌ماند.

### ویرایش وظیفه

`/jobs` ← انتخاب وظیفه ← **✏️ ویرایش**. قابل ویرایش: آدرس/پورت، یوزر، پسورد، نوع بکاپ، رمز بکاپ، زیپ، پوشه‌ی میکروتیک، مقصد و فاصله‌ی زمانی.

تغییر آدرس/یوزر/پسورد قبل از ذخیره با یک اتصال آزمایشی چک می‌شود؛ اگر وصل نشد، چیزی تغییر نمی‌کند. ذخیره‌ی آدرس (حتی همان قبلی) کلید SSH میکروتیک را دوباره می‌پذیرد؛ مثلاً بعد از ریست دستگاه.

### تلاش مجدد خودکار

اگر بکاپ **زمان‌بندی‌شده** شکست بخورد (اولین بکاپ بعد از ساخت وظیفه و «اجرا همین حالا» تلاش مجدد ندارند)، ربات به‌جای صبر تا نوبت بعدی، `RETRY_ATTEMPTS` بار دیگر و هر `RETRY_DELAY_MINUTES` دقیقه تلاش می‌کند. مالک وظیفه از همه‌چیز باخبر می‌شود:

- هر تلاش ناموفق: پیام با **علت واضح خطا** (مثلاً «احراز هویت ناموفق»، «اتصال رد شد»، «زمان اتصال تمام شد» + جزئیات فنی)، شماره‌ی تلاش (مثلاً «تلاش ۲ از ۴») و زمان تلاش بعدی
- موفقیت در یکی از تلاش‌های مجدد: پیام «در تلاش n موفق شد»
- شکست همه‌ی تلاش‌ها: پیام ناامیدی با آخرین خطا؛ نوبت بعدی طبق زمان‌بندی عادی اجرا می‌شود

**فقط خطاهای موقتی تلاش مجدد می‌گیرند:** timeout، رد شدن یا قطع شدن اتصال، خطای شبکه/DNS و خطاهای شبکه‌ی تلگرام. بقیه‌ی خطاها با صبر کردن درست نمی‌شوند و **تلاش مجدد ندارند**؛ همان بار اول پیام شکست با علت و راه‌حل مخصوص خودش می‌آید:

| خطا | راه‌حل اعلام‌شده |
|---|---|
| یوزر/رمز اشتباه | ویرایش یوزر/رمز |
| تغییر کلید SSH | ذخیره‌ی دوباره‌ی آدرس |
| دیسک/پوشه ناموجود یا پر بودن حافظه | ویرایش پوشه‌ی میکروتیک و بررسی فضای خالی |
| نبودن مجوز `ftp` برای کاربر روتر | افزودن مجوزهای لازم |
| دستگاه RouterOS نیست / مجوز کم | بررسی آدرس و مجوزها |
| حجم فایل بیش از ۵۰ مگابایت | بکاپ یک نوع یا کم کردن داده |
| شکست ساخت ZIP | خاموش کردن ZIP یا عوض کردن رمز |
| ربات از مقصد حذف شده / مجوز ندارد | دوباره ادمین کردن یا انتخاب مقصد دیگر |
| آدرس خصوصی/غیرمجاز | آدرس عمومی بدهید |
| خطای ناشناخته | بررسی تنظیمات و لاگ سرور |

هر کدام از این‌ها یک خطا برای شمارنده‌ی توقف خودکار حساب می‌شود.

**نکته‌ی امنیتی:** علت واضح فقط برای **وظیفه‌های موجود** نمایش داده می‌شود (مقصدشان هنگام ساخت با ورود موفق تأیید شده). تست اتصال در `/new` و ویرایش همچنان طبق تنظیمات ضد سوءاستفاده، خطای یکسان می‌دهد.

**نکته‌ها**

- اگر نوبت زمان‌بندی بعدی برسد، تلاش‌های مجدد در انتظار لغو و اجرای جدید جایگزین آن‌ها می‌شود. توقف یا حذف وظیفه هم تلاش‌های در انتظار را لغو می‌کند.
- تلاش‌های در انتظار در حافظه‌اند و با ری‌استارت ربات از بین می‌روند (زمان‌بندی عادی برقرار می‌ماند).
- با `RETRY_ATTEMPTS=0` تلاش مجدد خاموش می‌شود.

### سایر رفتارها

- **منطقه‌ی زمانی:** `/timezone` چند منطقه‌ی رایج یا «سایر» را پیشنهاد می‌دهد (نام IANA مثل `Asia/Tehran` یا اختلاف مثل `+03:30`). این تنظیم برای هر کاربر است و روی نام فایل‌ها، ساعت کپشن و «آخرین اجرا» اثر می‌گذارد.
- اگر نوع بکاپ «هر دو» باشد و یکی از فایل‌ها ساخته نشود (مثلاً پکیج `user-manager` نصب نیست)، فایل دیگر باز هم ارسال می‌شود و خطای بخش ناموفق به مالک اعلام می‌شود (وظیفه به‌خاطر آن متوقف نمی‌شود).
- هر وظیفه در هر لحظه فقط یک بکاپ در حال اجرا دارد؛ «اجرا همین حالا» در حین اجرای قبلی، اجرای دوم نمی‌سازد.
- اگر بکاپ وسط کار قطع شود (timeout)، فایل‌های موقت `tgbk-*` از روی میکروتیک پاک می‌شوند.
- ربات روی میکروتیک `/system backup save` (و `user-manager database save`) اجرا می‌کند، فایل را با SFTP می‌گیرد، از روی میکروتیک پاک می‌کند و در تلگرام می‌فرستد.
- بعد از **۵ خطای پیاپی** وظیفه خودکار متوقف می‌شود و به مالک خبر می‌دهد (هر «نوبت» که همه‌ی تلاش‌های مجددش شکست بخورد، یک خطا حساب می‌شود).
- برای کانال/گروه، ربات باید ادمین آن چت باشد و کاربر هم باید ادمین همان چت باشد.

## امنیت

- **اطلاعات رمزنگاری‌شده:** پسورد روتر، پسورد بکاپ و پسورد ZIP با Fernet رمزنگاری و در SQLite ذخیره می‌شوند. کلید از `FERNET_KEY` یا فایل `data/.secret.key` (با دسترسی `0600`) می‌آید. **از آن بکاپ بگیرید و محافظتش کنید.**
- **پین کردن کلید SSH (TOFU):** کلید هاست در اولین اتصال ذخیره و در اتصال‌های بعدی بررسی می‌شود. اگر میکروتیک را ریست کردید، `/jobs` ← وظیفه ← **ویرایش** ← **آدرس / پورت** را بزنید و همان آدرس را دوباره ذخیره کنید تا کلید جدید پذیرفته شود (نیازی به حذف و ساخت دوباره نیست).
- **جلوگیری از SSRF:** به‌طور پیش‌فرض آدرس‌های خصوصی/لوکال بلاک هستند (جلوگیری از اسکن شبکه‌ی سرور). آدرس یک بار resolve می‌شود و اتصال مستقیماً به همان IP انجام می‌شود (جلوگیری از DNS rebinding).
- **حتماً `ALLOWED_USERS` را تنظیم کنید.** اگر خالی باشد هر کسی می‌تواند از ربات استفاده کند و ربات به هر هاست/پورت عمومی SSH می‌زند.
- **جلوگیری از سوءاستفاده (پورت‌اسکن / brute-force):**
  - هر تست اتصال سهمیه دارد: هر کاربر ساعتی `TEST_LIMIT_PER_HOUR` بار، و هر مقصد (`host:port`) در کل ربات هر ۱۰ دقیقه `TARGET_LIMIT_PER_10MIN` بار. ویرایش آدرس/یوزر/پسورد هم تست حساب می‌شود؛ بکاپ‌های زمان‌بندی‌شده نه.
  - در ربات عمومی (`ALLOWED_USERS` خالی) همه‌ی شکست‌های اتصال یک پیام یکسان («اتصال برقرار نشد») و حداقل `CONN_FAIL_MIN_SECONDS` ثانیه زمان دارند، تا از روی متن خطا یا زمان پاسخ نشود فهمید پورت بسته است، فیلتر شده یا رمز غلط است. علت واقعی فقط در لاگ سرور (`INFO`) ثبت می‌شود. دو استثنا که قابل سوءاستفاده نیستند و برای خود کاربر مهم‌اند: تغییر کلید SSH میکروتیکِ ذخیره‌شده‌ی خودش، و «این RouterOS نیست» (فقط بعد از ورود موفق).
  - **لیست سفید:** آیدی کاربران قابل‌اعتماد را در `TRUSTED_USERS` بگذارید. این کاربران از سهمیه‌ی تست اتصال و از یکسان‌سازی خطا/زمان معاف‌اند (پیام خطای کامل می‌بینند و تأخیر ندارند). محدودیت‌های دیگر (آدرس‌های خصوصی، سقف تعداد وظیفه، حداقل بازه) برای آن‌ها هم برقرار است. این لیست جایگزین `ALLOWED_USERS` نیست: اگر `ALLOWED_USERS` پر باشد، کاربر لیست سفید هم باید در آن باشد.
  - روی سرور شخصی با `ALLOWED_USERS` پر، پیام‌های خطای کامل نمایش داده می‌شوند (با `HIDE_CONN_ERRORS=true` می‌توان رفتار یکسان را اجبار کرد).
- **ورودی محدود:** خروجی دستورها و اندازه‌ی فایل‌های دریافتی از روتر سقف دارد؛ یک سرور SSH مخرب نمی‌تواند حافظه را پر کند.
- **فایل‌های حساس:** فایل‌های بکاپ حاوی اطلاعات حساس‌اند؛ آن‌ها را فقط به چت خصوصی بفرستید و حتماً برای بکاپ رمز بگذارید.
- **محدودیت تلگرام:** فایل‌های بالای ۵۰ مگابایت ارسال نمی‌شوند.

## تنظیمات

همه‌ی تنظیمات متغیر محیطی‌اند و از فایل `.env` (یا از محیط کانتینر) خوانده می‌شوند.

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `BOT_TOKEN` | — | توکن ربات (**اجباری**) |
| `ALLOWED_USERS` | خالی | آیدی عددی کاربران مجاز، با کاما جدا شده. خالی = همه (توصیه نمی‌شود) |
| `TRUSTED_USERS` | خالی | آیدی عددی کاربران معاف از سهمیه‌ی تست اتصال و یکسان‌سازی خطا، با کاما جدا شده |
| `FERNET_KEY` | — | کلید رمزنگاری؛ اگر نباشد `data/.secret.key` ساخته می‌شود |
| `DATA_DIR` | `data` (در Docker: `/app/data`) | مسیر دیتابیس و کلید |
| `MAX_JOBS_PER_USER` | `5` | سقف وظیفه برای هر کاربر |
| `MIN_INTERVAL_MINUTES` | `10` | کمترین فاصله‌ی زمانی دلخواه |
| `MAX_PARALLEL_BACKUPS` | `3` | تعداد بکاپ همزمان در کل ربات |
| `ALLOW_PRIVATE_IPS` | `false` | اجازه‌ی آدرس‌های خصوصی/لوکال (فقط برای شبکه‌ی امن و مورد اعتماد) |
| `RETRY_ATTEMPTS` | `3` | تعداد تلاش‌های مجدد بعد از شکست بکاپ خودکار (`0` = خاموش) |
| `RETRY_DELAY_MINUTES` | `5` | فاصله‌ی بین تلاش‌ها به دقیقه |
| `TEST_LIMIT_PER_HOUR` | `10` | سقف تست اتصال برای هر کاربر در ساعت (`0` = خاموش) |
| `TARGET_LIMIT_PER_10MIN` | `5` | سقف تست اتصال به یک `host:port` در ۱۰ دقیقه، برای همه‌ی کاربران (`0` = خاموش) |
| `CONN_FAIL_MIN_SECONDS` | `20` | حداقل مدت هر تست ناموفق (برای یکسان‌سازی زمان پاسخ) |
| `HIDE_CONN_ERRORS` | `auto` | `auto` = یکسان‌سازی خطاها فقط وقتی `ALLOWED_USERS` خالی است؛ `true` / `false` برای اجبار |

## ارتقا از نسخه‌ی قبل

فقط فایل‌ها را جایگزین کنید و `pip install -r requirements.txt` بزنید (پکیج `pyzipper` برای ZIP رمزدار لازم است). با Docker دوباره build کنید: `docker compose --env-file .env -f docker/docker-compose.yml up -d --build`. ستون‌های جدید دیتابیس خودکار اضافه می‌شوند و وظایف قبلی دست‌نخورده می‌مانند (پوشه = روت، منطقه‌ی زمانی = UTC، زیپ = خاموش).
