# MikroTik Backup Bot

[English](README.md) | [Español](README.es.md) | **Русский** | [中文](README.zh.md) | [فارسی](README.fa.md)

Telegram-бот, который автоматически делает резервные копии ваших роутеров MikroTik и отправляет файлы в личный чат, группу или канал по выбранному вами расписанию.

Бот подключается к роутеру по SSH, создаёт бэкап, скачивает его по SFTP, удаляет с роутера и отправляет в Telegram. Каждую задачу можно изменить позже, а сам бот работает на языках 🇬🇧 English, 🇪🇸 Español, 🇷🇺 Русский, 🇨🇳 中文 и 🇮🇷 فارسی.

## Возможности

- **Типы бэкапа:** бинарный бэкап (`.backup`, с паролем или без), база User Manager (`.umb`) или оба сразу
- **ZIP по желанию:** обычный ZIP или ZIP с шифрованием **AES-256**
- **Гибкие получатели:** личный чат, группа или канал
- **Гибкое расписание:** варианты от 1 часа до 7 дней или свой интервал, например `30m`, `2h`, `1d` (до 30 дней)
- **Автоматические повторные попытки** при временных сбоях, с понятными сообщениями об ошибках и подсказками
- **Часовой пояс у каждого пользователя** для имён файлов, подписей и «последнего запуска»
- **Мультипользовательский режим:** лимит задач на пользователя, общий лимит параллельных бэкапов, контроль доступа
- **Безопасность по умолчанию:** шифрование учётных данных, закрепление ключа SSH-хоста, блокировка приватных IP, защита от злоупотреблений
- **Готов к Docker**, работает от непривилегированного пользователя

## Требования

- Python **3.10+** (или Docker)
- Токен бота от [@BotFather](https://t.me/BotFather)
- Роутер MikroTik с включённым SSH, доступным с сервера бота
- Python-зависимости: `python-telegram-bot[job-queue]`, `asyncssh`, `pyzipper`, `cryptography`, `python-dotenv`, `tzdata`

## Установка

### Вариант 1: Docker (рекомендуется)

```bash
git clone https://github.com/pouya6672/MikroTik-Backup-Telegram-bot.git
cd MikroTik-Backup-Telegram-bot
cp .env.example .env        # укажите BOT_TOKEN и ALLOWED_USERS
docker compose --env-file .env -f docker/docker-compose.yml up -d --build
docker compose -f docker/docker-compose.yml logs -f
```

- База данных и ключ шифрования хранятся в томе `mtbackup-data` (`/app/data`). **Всегда сохраняйте этот том.**
- Контейнер стартует от root только чтобы поправить права на том, затем через `gosu` переключается на непривилегированного пользователя `bot` (uid 10001).
- `docker/entrypoint.sh` проверяет все переменные окружения при запуске и выдаёт понятную ошибку (или предупреждение), если что-то не так: например, не задан `BOT_TOKEN`, неверный `FERNET_KEY` или пустой `ALLOWED_USERS`.
- Бот использует long polling, поэтому **открывать входящие порты не нужно**.

Без Compose:

```bash
docker build -f docker/Dockerfile -t mikrotik-backup-bot .
docker run -d --name mtbackup --restart unless-stopped \
  --env-file .env -v mtbackup-data:/app/data mikrotik-backup-bot
```

### Вариант 2: обычный Python

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # укажите BOT_TOKEN и ALLOWED_USERS
python bot.py
```

## Настройка MikroTik (для каждого роутера)

1. Убедитесь, что **сервис SSH** включён и доступен с сервера бота (порт 22 по умолчанию или любой другой):
   ```
   /ip service print
   ```
2. Создайте отдельного пользователя и разрешите вход только с IP сервера бота:
   ```
   /user add name=tgbackup group=full password=STRONG_PASSWORD address=BOT_SERVER_IP/32
   ```
   Группа `full` — самый простой вариант. Если вы создаёте более ограниченную группу, ей нужны как минимум политики: `ssh, ftp, read, write, policy, test, sensitive`.
3. Для бэкапа User Manager на роутере должен быть установлен пакет `user-manager`.

## Использование

| Команда | Описание |
|---|---|
| `/new` | Создать задачу бэкапа |
| `/jobs` | Список задач: запуск сейчас, изменение, пауза/возобновление, удаление |
| `/timezone` | Задать часовой пояс |
| `/language` | Сменить язык бота |
| `/cancel` | Отменить текущий шаг |

### Создание задачи (`/new`)

1. **Адрес:** IP или домен, при желании с портом SSH (`1.2.3.4` или `1.2.3.4:2222`)
2. **Имя пользователя**
3. **Пароль:** ваше сообщение удаляется сразу после прочтения, а подключение проверяется немедленно
4. **Тип бэкапа:** MikroTik / User Manager / оба, с паролем бэкапа или без
5. **ZIP** (необязательно): без ZIP / ZIP без пароля / ZIP с паролем
6. **Временная папка на роутере**
7. **Получатель:** личный чат, группа или канал
8. **Интервал:** 1 час … 7 дней или свой (`30m`, `2h`, `1d`)

### ZIP-архивы (необязательно)

Если включено, все файлы одного запуска упаковываются в **один ZIP**, и отправляется именно он, например `MyRouter_2026-01-31_12-00.zip` с файлом `.backup` и, если выбрано «оба», ещё и `.umb`. По умолчанию выбрано «без ZIP», поэтому старые задачи работают как раньше.

- **Без пароля:** обычный ZIP (Deflate).
- **С паролем:** ZIP с шифрованием **AES-256** (стандарт WinZip). Открывается в 7-Zip, WinRAR, Keka, The Unarchiver и подобных программах. Встроенный распаковщик Проводника Windows AES не поддерживает. Старый слабый метод ZipCrypto намеренно не используется.
- Пароль ZIP не зависит от пароля бэкапа MikroTik. Можно задать оба (зашифрованный бэкап внутри зашифрованного ZIP).
- Если создать ZIP не удалось, файлы без архива **не отправляются**, чтобы файл, который вы хотели зашифровать, никогда не ушёл без защиты. Владельцу приходит сообщение об ошибке.
- Итоговый ZIP тоже должен укладываться в лимит Telegram 50 МБ.
- Изменить можно позже: `/jobs` → задача → **✏️ Изменить** → **🗜 ZIP**.

### Папка на роутере

Путь вроде `flash/backups`, `disk1/mt-backup` или `backups`. Отправьте `-` (или нажмите кнопку по умолчанию), чтобы использовать корень роутера.

- Отсутствующие папки (включая вложенные) создаются перед каждым бэкапом командой `/file add type=directory`. На версиях без этой команды папка создаётся при сохранении файла.
- Если диска (`flash`, `disk1`, `usb1`, …) нет, бот сообщает об этом понятной ошибкой.
- После скачивания файлы удаляются с роутера; сама папка остаётся.

### Изменение задачи

`/jobs` → выберите задачу → **✏️ Изменить**. Можно изменить: адрес/порт, имя пользователя, пароль, тип бэкапа, пароль бэкапа, ZIP, папку на роутере, получателя и интервал.

Изменения адреса/пользователя/пароля перед сохранением проверяются пробным подключением; если оно не удалось, ничего не меняется. Сохранение адреса (даже того же самого) заново принимает SSH-ключ роутера — это нужно, например, после сброса устройства.

### Автоматические повторные попытки

Если **запланированный** бэкап не удался (первый бэкап после создания задачи и «Запустить сейчас» не повторяются), бот не ждёт следующего запуска, а делает ещё до `RETRY_ATTEMPTS` попыток с интервалом `RETRY_DELAY_MINUTES` минут. Владелец задачи получает уведомления обо всём:

- каждая неудачная попытка: сообщение с **понятной причиной** (например, «ошибка аутентификации», «соединение отклонено», «время подключения истекло» плюс технические детали), номером попытки («попытка 2 из 4») и временем следующей
- успех при повторной попытке: «выполнено с попытки n»
- все попытки провалились: итоговое сообщение с последней ошибкой; следующий запуск идёт по обычному расписанию

**Повторяются только временные ошибки:** тайм-ауты, отклонённые или оборванные соединения, сетевые/DNS-ошибки и сетевые ошибки Telegram. Остальные ошибки ожиданием не исправить, поэтому они **не повторяются**; сообщение о сбое приходит сразу, с конкретным решением:

| Ошибка | Подсказка |
|---|---|
| Неверный логин/пароль | Изменить логин/пароль |
| Изменился SSH-ключ хоста | Заново сохранить адрес |
| Диска/папки нет или память заполнена | Изменить папку на роутере и проверить свободное место |
| У пользователя роутера нет политики `ftp` | Добавить нужные права |
| Устройство не RouterOS / недостаточно прав | Проверить адрес и права |
| Файл больше 50 МБ | Делать бэкап одного типа или уменьшить объём данных |
| Не удалось создать ZIP | Отключить ZIP или сменить пароль |
| Бот удалён из чата-получателя / нет прав | Снова назначить админом или выбрать другого получателя |
| Приватный/недопустимый адрес | Указать публичный адрес |
| Неизвестная ошибка | Проверить настройки и лог сервера |

Каждая из этих ошибок засчитывается как сбой для автоматической паузы.

**Замечание по безопасности:** подробная причина показывается только для **существующих задач** (получатель которых был проверен при создании). Проверки подключения в `/new` и при изменении подчиняются настройкам защиты от злоупотреблений и при необходимости возвращают единое сообщение об ошибке.

**Примечания**

- Когда наступает время следующего запуска, ожидающие повторные попытки отменяются, и вместо них выполняется новый запуск. Пауза или удаление задачи тоже отменяет ожидающие повторы.
- Ожидающие повторные попытки хранятся в памяти и пропадают при перезапуске бота (обычное расписание не затрагивается).
- `RETRY_ATTEMPTS=0` отключает повторные попытки.

### Прочее поведение

- **Часовой пояс:** `/timezone` предлагает популярные пояса или «Другой» (имя IANA, например `Asia/Tehran`, или смещение, например `+03:30`). Настройка своя у каждого пользователя и влияет на имена файлов, время в подписях и «последний запуск».
- При типе «оба», если один файл создать не удалось (например, не установлен пакет `user-manager`), второй всё равно отправляется, а об ошибке неудавшейся части сообщается владельцу. Задача из-за этого не приостанавливается.
- У каждой задачи одновременно выполняется не более одного бэкапа; «Запустить сейчас» во время выполнения не создаёт второй запуск.
- Если бэкап прерван (тайм-аут), оставшиеся временные файлы `tgbk-*` удаляются с роутера.
- На роутере бот выполняет `/system backup save` (и `user-manager database save`), скачивает файл по SFTP, удаляет его с роутера и отправляет в Telegram.
- После **5 сбоев подряд** задача автоматически приостанавливается, и владельцу приходит уведомление (один «сбой» — это целый запуск, все повторные попытки которого не удались).
- Для **канала или группы** бот должен быть администратором этого чата, и пользователь тоже.

## Безопасность

- **Шифрование секретов:** пароль роутера, пароль бэкапа и пароль ZIP шифруются с помощью Fernet и хранятся в SQLite. Ключ берётся из `FERNET_KEY` или из `data/.secret.key` (создаётся с правами `0600`). **Сделайте его резервную копию и защитите.**
- **Закрепление SSH-ключа хоста (TOFU):** ключ хоста сохраняется при первом подключении и проверяется при последующих. После сброса роутера откройте `/jobs` → задача → **Изменить** → **Адрес / порт** и снова сохраните тот же адрес, чтобы принять новый ключ; удалять и создавать задачу заново не нужно.
- **Защита от SSRF:** приватные/локальные адреса по умолчанию заблокированы (чтобы бот не мог сканировать сеть самого сервера). Адрес разрешается один раз, и подключение идёт прямо на этот IP, что исключает DNS rebinding.
- **Обязательно задайте `ALLOWED_USERS`.** Если он пуст, ботом может пользоваться кто угодно, и бот будет подключаться по SSH к любому публичному хосту и порту.
- **Защита от злоупотреблений (сканирование портов / перебор паролей):**
  - Каждая проверка подключения ограничена: `TEST_LIMIT_PER_HOUR` на пользователя и `TARGET_LIMIT_PER_10MIN` на `host:port` для всего бота. Изменение адреса/пользователя/пароля считается проверкой; плановые бэкапы — нет.
  - В публичном боте (`ALLOWED_USERS` пуст) все сбои подключения возвращают одинаковое сообщение («не удалось подключиться») и длятся не меньше `CONN_FAIL_MIN_SECONDS`, чтобы ни по тексту ошибки, ни по времени ответа нельзя было понять, закрыт ли порт, фильтруется ли он или неверен пароль. Реальная причина пишется только в лог сервера (`INFO`). Два исключения, которыми нельзя злоупотребить и которые важны самому пользователю: смена SSH-ключа его *собственного* сохранённого роутера и «это не RouterOS» (только после успешного входа).
  - **Белый список:** укажите ID доверенных пользователей в `TRUSTED_USERS`. Они освобождены от квот на проверки и от единообразия ошибок/времени (видят полные ошибки и без задержки). Остальные ограничения (приватные адреса, лимит задач, минимальный интервал) для них сохраняются. Этот список не заменяет `ALLOWED_USERS`: если `ALLOWED_USERS` задан, доверенный пользователь тоже должен в нём быть.
  - На личном сервере с заполненным `ALLOWED_USERS` показываются полные сообщения об ошибках (единообразное поведение можно принудительно включить через `HIDE_CONN_ERRORS=true`).
- **Ограниченный ввод:** вывод команд роутера и размер скачиваемых файлов ограничены, поэтому вредоносный SSH-сервер не сможет исчерпать память.
- **Конфиденциальные файлы:** бэкапы содержат чувствительные данные. Отправляйте их только в личные чаты и всегда задавайте пароль бэкапа.
- **Лимит Telegram:** файлы больше 50 МБ отправить нельзя.

## Настройка

Все параметры — переменные окружения, загружаются из `.env` (или передаются контейнеру).

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота (**обязательно**) |
| `ALLOWED_USERS` | пусто | Числовые Telegram ID пользователей, которым разрешено пользоваться ботом, через запятую. Пусто = все (не рекомендуется) |
| `TRUSTED_USERS` | пусто | ID через запятую, освобождённые от квот проверки подключения и единообразных ошибок |
| `FERNET_KEY` | — | Ключ шифрования. Если не задан, создаётся `data/.secret.key` |
| `DATA_DIR` | `data` (`/app/data` в Docker) | Расположение базы данных и ключа |
| `MAX_JOBS_PER_USER` | `5` | Лимит задач на пользователя |
| `MIN_INTERVAL_MINUTES` | `10` | Минимальный допустимый пользовательский интервал |
| `MAX_PARALLEL_BACKUPS` | `3` | Число одновременных бэкапов на весь бот |
| `ALLOW_PRIVATE_IPS` | `false` | Разрешить приватные/локальные адреса (только в изолированной доверенной сети) |
| `RETRY_ATTEMPTS` | `3` | Число повторных попыток после неудачного планового бэкапа (`0` = выключено) |
| `RETRY_DELAY_MINUTES` | `5` | Минут между повторными попытками |
| `TEST_LIMIT_PER_HOUR` | `10` | Проверок подключения на пользователя в час (`0` = выключено) |
| `TARGET_LIMIT_PER_10MIN` | `5` | Проверок подключения к одному `host:port` за 10 минут, для всех пользователей (`0` = выключено) |
| `CONN_FAIL_MIN_SECONDS` | `20` | Минимальная длительность неудачной проверки (выравнивание времени ответа) |
| `HIDE_CONN_ERRORS` | `auto` | `auto` = единые ошибки только при пустом `ALLOWED_USERS`; `true` / `false` для принудительного значения |

Генерация ключа:

```bash
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Чтобы узнать свой числовой Telegram ID, напишите боту вроде [@userinfobot](https://t.me/userinfobot).

## Обновление

Замените файлы и выполните `pip install -r requirements.txt` (для шифрованного ZIP нужен пакет `pyzipper`). В Docker пересоберите образ: `docker compose --env-file .env -f docker/docker-compose.yml up -d --build`. Новые столбцы базы данных добавляются автоматически, существующие задачи продолжают работать (папка = корень, часовой пояс = UTC, ZIP = выключен).
